FOK versus IOC

FOK requires the entire amount immediately or nothing. IOC allows a partial immediate fill, cancels what remains, and never rests. A limit order may leave unfilled quantity resting.

OWNERSHIP & CONFIDENCE

“What if they think I used AI?”

The solution is not a better disguise. It's knowing what was actually done, what you personally understand, and where the limits are.

The honest version of your story

“I worked on a C++ limit order book and a Python microstructure analysis project. I used AI-assisted code review and debugging to identify and patch several edge cases, then used GitHub Actions to check the builds and tests. I’m working through the reasoning behind those fixes and can explain the behavior and trade-offs.”

Adapt this to precisely reflect what you did. Don't claim you wrote every patch without help. Don't claim every recent CI job passed unless confirmed.

What you can confidently own

  • Show how a buy order sweeps the asks.
  • Explain why FIFO within a price level matters.
  • Explain the unordered price-bucket tradeoff.
  • Describe what a FOK pre-check protects.
  • Explain how to reproduce and test a bug.

What you shouldn't pretend

  • That CI passing proves financial profitability.
  • That synthetic data represents real exchange flow.
  • That you wrote code yourself if someone asks about AI assistance.
  • That every edge case has been exhaustively validated.
  • That benchmark ticks/sec equals end-to-end trading latency.

If you get stuck: say “I haven't verified that specific case. My understanding is X; I would test it by Y.” That is a valid engineering answer. Making up a runtime guarantee is not.
